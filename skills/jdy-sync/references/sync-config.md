# 同步配置写法

**先用 `init_config.py` 生成草稿**，不要从零手写：

```bash
python3 scripts/init_config.py --source <源app_id> --target <目标app_id> --out 同步.yaml
```

它会自动配对同名表单、推荐业务键（含唯一度与填充率）、猜异名字段映射、
识别关联字段的指向，并把未配对的表单列在末尾。下面是最终格式说明。

YAML（也接受 `.json`）。

```yaml
name: 演示同步
source:
  app: <源 app_id>
target:
  app: <目标 app_id>
id_map: ./idmap.json        # ID 映射表落盘位置，断点续跑与增量都靠它
                            # 相对路径按**配置文件所在目录**解析，与备份文件同一规则

tables:
  - alias: parent           # 本配置内的唯一标识，供 refs 引用
    source_entry: "<源 entry_id>"
    target_entry: "<目标 entry_id>"
    key: 编码                # 业务键：判断目标端是否已存在这条记录
    limit: 3                # 可选。只取源表前 N 条——全量跑之前先小范围验口径

  - alias: child
    source_entry: "<源 entry_id>"
    target_entry: "<目标 entry_id>"
    key: 单号
    fields:                 # 可选。缺省按显示名同名映射
      源字段名: 目标字段名
    refs:                   # 关联数据字段 → 指向本配置里哪张表
      关联父项: parent
```

## `key`：业务键

判断"目标端已经有这条了吗"。必须在源表和目标表都存在（改过名就在 `fields` 里映射）。

- 业务键为空的记录会被**拦下**并报 `missing_key`——无法判断是否已存在，就不能瞎写
- 目标端同一业务键有多条时取第一条；建议先用 `jdy-doc` 体检确认唯一性

## `refs`：关系怎么搬

`refs` 的键是**源表里的关联数据字段名**，值是**本配置里被引用表的 alias**。

引擎据此：

1. 把被引用的表排到前面同步（拓扑序）
2. 用 ID 映射把源端引用值翻译成目标端 data_id
3. 翻译不出来的**不写**，报 `unresolved_ref`

> 目标字段必须是**关联数据（`lookup`）**。若是**选择数据（`linkdata`）**，
> 接口不支持写入，计划阶段会列进"搬不过去的字段"。

## `fields`：字段映射（**白名单**）

缺省按显示名同名映射，把两边同名的字段全搬。

**一旦写了 `fields`，就只搬列出的字段**——同名字段不再自动带上。
这是有意的（你可能就想只搬一部分），但容易踩：漏列的字段会整列为空。

所以计划里会把「两边同名但没写进 `fields`」的字段**显式列出来**，
不会让它们凭空消失。`init_config.py` 生成草稿时也会把**全部**可搬字段写进
`fields`，而不只是改名的那几对。

计划阶段会把搬不过去的列出来，分三类：目标表没有该字段、目标字段是选择数据、
目标字段由系统生成（流水号）。

## 大批量写入的确认码

改动超过 50 条时 `apply.py` 会拒绝执行（退出码 5）并打印一个 8 位确认码，
需带 `--confirm-code` 重跑。

`--confirm-threshold` 只能把这个 50 **往小调**（传更大的数会被夹回 50——否则 `--confirm-threshold 999999` 就等于把闸门拆了）。**几乎不需要动，也不该拿去问用户**——
用户关心的是"搬多少条"（`limit`），不是"到第几条开始要确认"。
两个都是数字，混在一起讲只会让人迷糊。

码由**本次计划内容**算出（目标应用 + 各表增改条数 + 业务键），
所以源数据一变码就变——**旧码失效意味着计划变了，应当重新看一遍**。

## 常见问题

- **第二次同步全变成新增** → ID 映射表没落盘。检查 `id_map` 路径是否可写；
  apply 会在写不下去时明确警告
- **换个目录跑，映射表像是空的** → 已修：相对路径按配置文件所在目录解析，
  不再受当前工作目录影响。旧版本会在新目录另建一份，两份悄悄分裂
- **引用列是空的** → 看计划里的 `unresolved_ref`；多半是被引用表还没同步，
  或者被引用记录的业务键为空导致没匹配上
- **某一列同步后为空** → 看回读核对报告。若该列是选择数据，那是接口限制不是 bug
