# jdy-query 临时查数与即席报告

## 和 jdy-report 的分工

| | jdy-report | jdy-query |
|---|---|---|
| 场景 | **周期性**报表：周报、月报 | **一次性提问**："华东区这月多少单" |
| 定义 | YAML 报表定义，可复用 | 命令行参数，用完就扔 |
| 产出 | Markdown，可推群机器人 | 自包含 HTML 页面，带图 |

用户问的是"这周数据怎么样、每周五发我"→ jdy-report；
问的是"帮我看看按行业分下来什么样"→ jdy-query。

## 三个坑（自己写代码也一样要躲）

查数是只读的，你完全可以自己写脚本——很多时候那样更快。但下面三条是
**简道云特有的陷阱**，踩了不会报错，只会给出一个看起来很正常的错数字：

1. **筛选字段名写错 = 不筛选。** 简道云对不认识的字段**既不报错也不过滤**，
   直接返回全表。你会拿到 206 行然后当成"筛选结果"报给用户。
   自己写就自己校验：先取 `widget/list`，确认字段标识真的存在再发查询。
2. **求和/求平均遇到非数值。** 当成 0 会把平均值悄悄拉低。应当跳过，
   并且**把分母交代清楚**——"平均 X（基于 N 条有值记录，共 M 条）"。
3. **分组时的空值不能丢。** 它常常是最大的一组，含义是"这字段大部分没人填"，
   丢掉等于隐瞒。归入 `(未填)` 并单独说一句。

另外：把字段值拼进 HTML 时**必须转义**。业务数据里出现 `<` 的概率不低，
不转义轻则页面错版，重则注入。

用本技能的 `query.py` 这四条已经替你做了；自己写就自己补上。

## 用法

```
python3 scripts/query.py --list                                   # 先列应用/表单
python3 scripts/query.py --app <应用> --entry <表单> --where '职务=CEO'
python3 scripts/query.py --app <应用> --entry <表单> --group-by 职务 --top 8 \
        --out 报告.html
python3 scripts/query.py --app <应用> --entry <表单> \
        --group-by 产品分类 --metric sum:产品定价 --out 报告.html
```

- `--where` 写 `字段=值` 或 `字段:method:值`（`;` 连多条）。
  **字段写显示名就行**，认不出来会直接报错——
  简道云对不认识的字段**既不报错也不过滤**，会返回全表，
  调用方还以为筛过了。
- `--metric`：`count`（默认）/ `sum:列` / `avg:列` / `max:列` / `min:列`
- `--out` 生成 HTML；`--json-out` 另存结构化结果

## 呈现建议

- **先回答问题，再给页面。** 用户问"有多少"，第一句就该是那个数字，
  不是"我生成了一份报告"
- 分组结果里的 **`(未填)`** 要单独说一句。它常常是最大的一组，
  但它的含义是"这个字段大部分没人填"，不是一个业务分类
- 用了 `--top` 就说清楚"图里只有前 N 组，共 M 组"——页面里已经写了，
  对话里也别漏
- 非数值的格子在求和/求平均时**被跳过而不是当 0**，
  所以"平均值"的分母可能小于总行数；口径要交代

## 安全边界

- 全程只读：只调 `app/list`、`entry/list`、`widget/list`、`data/list`
- 生成的 HTML **不引任何外部资源**，样式与图表全部内联，
  可以直接发给别人，不会因为断网或跨域出问题
- 密钥读 `JDY_API_KEY` 或 `~/.jdy/config.json`，绝不写进生成物
