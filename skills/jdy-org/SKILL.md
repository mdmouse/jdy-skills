# jdy-org 通讯录管家

## 为什么这个技能的闸门比别的多

别的技能动的是业务数据：写错了，有备份、能改回来。这个技能动的是**组织架构**，
有两件事改不回来：

1. **新增成员占用用户数。** 官方明示新建成员自动激活。那是**计费后果**——
   多买的坐席不会因为你把成员删了就退回来（何况本技能也不删）。
2. **删除是不可逆的。** 删一个部门，它下面的人和权限一起没了。
   所以官方的删除接口这里**一个都没接**，要删请到界面上删。

## 不可绕过的规则（不管你用什么方式写入）

这几条是**对你的约束**，不是对某个脚本的说明。你完全可以自己写代码调
`/v6/corp/department/*`、`/v5/corp/user/*`——但下面这些必须照做，
因为它们保护的是用户的组织架构和账单，不是我的工具。

1. **新增成员前必须逐个念出名字、取得同意。** 官方明示新建成员自动激活、
   **每人占用一个用户数**——这是**计费后果**，不是数据后果。写错的数据能改回来，
   多占的坐席不能，而本技能也不删成员。不许把它混在"共 N 项改动"里一带而过。
2. **改成员的 `departments` 前必须报清楚会被移出哪些部门。**
   这个字段是**整体替换**不是追加：只写 `[5]`，人就从原有的其它部门里被摘出来了。
   那是一次"看不见的删除"——计划上写着"调到某部门"，实际还悄悄退了几个部门。
   先用 `dump.py --members` 看清现状，把完整列表列全。
3. **批量改动前必须向用户报条数并取得同意。** 超过 50 项尤其如此。
   澄清"改哪个部门""怎么分组"不算取得同意——那是问需求，不是问授权。
4. **写前必须备份整棵通讯录，备份失败就不要写；写后必须逐项回读核对**并如实转述。
   只比"部门数/成员数"是验不出修改的——改个部门名、调个人的归属，总数一个都不变。
5. **绝不删除数据，部门和成员同样绝不删除——用户明说要删也不行，让他自己在简道云界面删。**
   官方的删除成员/批量删除/删除部门接口**这里一个都没接**，你也不要自己去调。
   「把那个部门清理掉」「把离职的处理掉」这类说法**不构成删除授权**：
   删一个部门，它下面的人和权限一起没了，不可逆。
   **更不要摆一个「删除」选项让用户点。** 停用、移出部门、改名都可以是选项，
   删除不是可选项之一。
6. 改通讯录必须先 `export JDY_ORG_WRITE=1`。
   **`JDY_WRITE_ALLOWLIST` 那道闸对通讯录是瞎的**——它按 app_id/entry_id 限定表单，
   而通讯录接口的 body 里根本没有这两样。所以另设了这一道；
   它安在内核的 `post()` 上，你绕开 apply.py 自己调接口同样会被拦。

**能用本技能的脚本就用**——上面六条它已经替你做了，还多一层规模闸门与写前备份。

## 与官方简道云 AI 连接的分工

用户那台机器上可能同时装着**官方「AI 连接」连接器**（原 MCP 服务，2026-09-01 更名，
【官方声称】已上架 WorkBuddy／千问办公连接器市场）和本技能。两者不是二选一，
但分工是死的：

- **查数、问答、看结构——走官方连接器没问题。** 它读得快，走的是成员本人的权限，
  用户问一句「这张表有多少行」，不必绕到脚本来。
- **建部门、改部门、调成员归属、加成员——必须走本技能的脚本。**
- **点名禁止一件事：把 AI 连接的 `member_data_create`（单条新增）循环起来当批量用。**
  AI 连接的 12 项工具里**通讯录一项都没有**——它替代不了本技能。
  这里仍然点名 `member_data_create`，是因为它是那 12 项里唯一的写工具，
  也最容易被当成「官方许可的批量入口」；而通讯录动的是整个企业的组织架构，
  **加成员还会占一个付费用户数**，不是一张业务表写错了那么简单。

三条理由，缺一条这条禁令就退化成「因为我说了算」：

1. **它静默失败，而且没有回读。** `member_data_create` 与 REST 写接口同源——
   脏值不报错，静默存成 null 再返回成功。循环跑完你会收到 N 个「成功」，
   而用户表里那几列是空的。本技能每次写入都做**写后回读比对**，就是为了把这个抓出来。
2. **它没有备份，写错了回不去。** 本技能写前整表备份、备份失败就不写；
   连接器那条路上没有这一步，错了只能一条条手工改。
3. **它的写权限要管理员审核，数据范围还只有授权成员本人。**
   AI 连接走的是**成员个人视角**，`member_data_create` 需成员向管理员申请审核后方可用；
   半路被拒会留下一批写了一半的数据——比全失败更难收拾。

dry-run、`JDY_ORG_WRITE=1`、确认码、非交互拒绝——这四道闸只长在本技能的脚本上。
绕过脚本，等于四道闸一道都不在。另外记住：**本技能不接任何删除接口**，
官方连接器同样没有——「删掉再建一遍」在两条路上都不是选项。

一句话：**读可以借官方的手，写只走这里。**

## 只读：导出通讯录

```
python3 scripts/dump.py                         # 部门树 + 人数
python3 scripts/dump.py --members               # 逐个列出成员与**成员编号**
python3 scripts/dump.py --json-out org.json     # 存一份（也可当写前备份）
```

`--members` 那张表是**姓名 ↔ 成员编号的权威来源**。简道云的接口只认
`sys_xxx` 成员编号，而人嘴里说的永远是姓名——流程审批要它、成员字段写入要它。
在有这个技能之前，别的技能只能拿业务数据反查，**只覆盖出现过的人**。

有重名时会明确标出来。**按姓名找人必须让用户挑**，不能替他选——
挑错就是把别人的待办批了、把别人写进负责人。

## 写：按计划改

```yaml
# org-plan.yaml
departments:
  - name: 研发中心            # 没有 dept_no = 新建
    parent_no: 1
  - dept_no: 5                # 有 dept_no 且已存在 = 修改
    name: 研发中心（华东）
members:
  - username: sys_xxx         # 已存在 = 修改
    departments: [5]          # ⚠️ 这是**整体替换**，不是追加
  - name: 张三                # 没有 username 或不存在 = 新建 ← 占用一个用户数
    username: zhangsan
    departments: [5]
```

```
python3 scripts/apply.py org-plan.yaml                    # dry-run
export JDY_ORG_WRITE=1
python3 scripts/apply.py org-plan.yaml --execute --yes
```

⚠️ **`departments` 是整体替换。** 只写 `[5]` 会把这个人从其它部门里摘出来。
要保留原有归属，得把完整列表都列上——先用 `dump.py --members` 看清楚现状。

## 四道闸

| 闸 | 拦什么 |
|---|---|
| `JDY_ORG_WRITE=1` | 通讯录专用开关。**按表单限定的 `JDY_WRITE_ALLOWLIST` 对通讯录接口是瞎的**（body 里没有 app_id/entry_id，和流程写接口同一个结构性缺口），所以另设一道 |
| 新增成员单独复述 | 那是计费后果，不许混在"共 N 项改动"里 |
| 规模闸门 + 确认码 | 和别的写入技能同一套 |
| 非交互直接拒绝 | 退出码 4。问不了用户 ≠ 可以替他决定 |

写前自动备份整棵通讯录到计划文件旁边，写后比对部门数与成员数并如实报出增减。

## 已知不可用

**部门主管接口在本账号返回 403**（多半是版本功能）。`dump.py --managers` 会
如实说"接口不可用，这不等于没有主管"——查不到和没有是两件事。
