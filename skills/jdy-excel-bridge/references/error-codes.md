# 错误归因对照表

分两类：**会报错的**（少）和**静默失败的**（多，且危险）。

## 一、静默失败——不报错，但数据是错的

这些情况接口一律返回 `{"status":"success"}`，只能靠**预检拦截**或**回读比对**发现。

| 现象 | 成因 | 修复动作 |
|---|---|---|
| 整行数据全空 | 写入值没有 `{"value": x}` 包裹 | 内核已强制包裹；若出现说明调用方绕过了 `encode_row` |
| 子表单整块为空 | 子表单**内层**字段用了裸值 | 内外两层都要包裹 |
| 日期列全空 | 用了 `2026/08/27`、`27/08/2026`、`2026年8月27日` 等格式 | 预检的日期归一化会转成 ISO-UTC |
| 日期差 8 小时 | 不带时区的本地时间被当成 UTC 收下 | 归一化时按本地时区转 UTC；Excel 里已是 UTC 就加 `--utc` |
| 数字列为空 | 值不可解析为数字（如 `abc`、`约100`） | 预检报 `bad_value`，让用户改单元格 |
| 成员列为空 | 传了显示名或成员对象，接口只认 `username` | 预检查历史数据反解；查不到要用户提供 username |
| 关联列恒为空 | `linkdata`（**选择数据**）无法 API 写入，官方明示 | 无解——界面手工补录，或改用「关联数据」(`lookup`) 字段承载 |
| 关联列写进去了但指向虚无 | `lookup`（**关联数据**）可写，但**接口不校验引用是否存在** | 预检会查目标记录在不在（`lookup_missing`）。这类脏数据**回读比对也发现不了**，因为写什么读什么 |
| 多出来的列没生效 | 表单里不存在该字段，接口静默忽略 | 预检列出"Excel 有但表单没有的列" |
| 流水号重复 | `sn` 由系统计数器生成，可能与既有数据冲突 | 导入前后核对编号唯一性；冲突需在界面处理 |

## 二、会报错的——结构性问题

| HTTP | code | msg | 成因 | 修复 |
|---|---|---|---|---|
| 400 | `17024` | The batch creation at one time exceeds the limit. | `data_list` > 100 条 | 内核自动分块 ≤100 |
| 400 | `3005` | The request contains invalid parameter(s). | `data_list` 为空数组 | 提交前过滤空批次 |
| 400 | `8303` | 超出请求频率限制 | 超过端点频率（batch_create 10/秒） | 令牌桶限流 + 指数退避 |
| 400 | `3005` | The request contains invalid parameter(s). | 清空字段时传了 `null` 或空串 | 清空只认空对象 `{"value": {}}` |
| 400 | `4001` | Data does not exist. | `data/get` 的 data_id 不在这张表里 | 反查目标表时正常，据此判断引用是否有效 |
| 403 | `8302` | Do not have permission for the API calls. | 调了本版本没买的接口（审计日志＝旗舰版） | 换版本，或把该能力做成「探到权限才启用」 |
| — | `NO_KEY` | — | 找不到密钥 | 设 `JDY_API_KEY` 或写 `~/.jdy/config.json` |

> 权限类、鉴权类错误码尚未采集完整——需用最小权限 Key 做越权调用后补。

## 三、响应字段的坑

同一 `transaction_id` 二次提交时，数据**会被覆盖**，但响应的 `success_ids` 是**空数组**、
`success_count` 仍为 1。判定成功看 `success_count`，取数据 ID 看 `success_ids`，
不要用 `success_ids` 的长度判断成败——否则会误判失败并无限重试。
