# 体检规则与判定依据

每条规则都要能回答"为什么这是个问题"。查得出但说不清影响的规则，不如不查。

| 规则 | 严重度 | 判定 | 为什么是问题 |
|---|---|---|---|
| 含不可 API 导入的关联字段 | 高 | 表单含 `linkdata` 类型字段 | 实测十种写法均无法通过 API 写入且**不报错**。Excel 导入时该列必然为空——"导入成功但数据不对"的头号成因 |
| 字段数接近上限 | 中／高 | 字段数 ≥ 340（上限 400 的 85%），达到 400 记高 | 加不了新字段，必须拆表；大表单的导出与聚合也明显更慢 |
| 流水号存在重复风险 | 中 | 表单含 `sn` 类型字段 | 流水号由系统计数器生成，实测计数器可能与既有数据不同步（新建行拿到了已被占用的编号） |
| 字段仍用默认名（带序号） | 中 | 字段名匹配 `^(控件类型名)_\d+$` | `单行文本_1` 这类名字人和 AI 都认不出含义，Excel 表头匹配不上，导入映射直接失败 |
| 字段名与控件类型同名 | 低 | 字段名等于裸控件类型名（无序号） | 不一定是问题——`附件`、`签名` 常是有意命名。同一表单出现多个时才难区分 |
| 疑似孤儿字段 | 低 | 抽样 ≥5 行，某字段在所有抽样行中均为空 | 可能是废弃字段。徒增表单复杂度与导入映射负担。**抽样结论，不是定论**——低频字段会被误报 |

## 判定口径说明

- **子表单内部字段一并纳入**关联字段、流水号、默认名、字段数的统计（子表单字段同样占用配额）
- **孤儿字段只看顶层字段**，不下钻子表单——子表单行数少时误报率过高
- 抽样行数默认 30，用 `--samples` 调整。抽得越多越准，代价是更多 `data/list` 调用（30 次/秒限流）
- 空值判定：`None` / `""` / `[]` / `{}` 四者都算空

## 有意不做的检查

- **必填校验缺失**：`widget/list` 的返回里没有必填标记，拿不到这个信息
- **成员/部门引用失效**：需要逐条比对通讯录，成本高且误报率高，留待有明确需求再做
- **流程节点**：流程相关接口尚未实测，不做无依据的判断
