# jdy-watch 数据哨兵

## 为什么是轮询

简道云的数据推送（Webhook）要一个**公网可达的服务端**接收回调。这套技能跑在
桌面 Agent 里——没有公网入口，但有定时任务。所以走本地轮询。

代价说清楚：**有间隔，不是实时**；而且改动检测只能靠本地比对——实测简道云的
`filter` 对 `updateTime`／`createTime` 这些系统字段**一律静默忽略**（照常返回
200、给你整表），所以没有"只拉改过的行"这条路，每轮都是全量拉回来自己比。
表很大时把 `limit` 调小，或者用 `when` 先筛一道。

## 三步

```
python3 scripts/watch.py 规则.yaml                      # 只汇总，不发
python3 scripts/watch.py 规则.yaml --webhook <URL>      # 预览要发什么
python3 scripts/watch.py 规则.yaml --send --yes         # 确认后真发
```

规则文件写法见 [references/watch-rules.md](references/watch-rules.md)。

## 两类规则

**阈值型**（`when`）：当前满足条件就报。库存低于 10、金额超过 5 万、状态是「异常」。

**新增型**（`new_rows: true`）：只报没见过的记录。新订单、新线索、新工单。

⚠️ **新增型第一次跑只建基准、不提醒。** 第一次没有基准，此时把整表当成"新增"
全推出去是灾难——一张两千行的表会变成一条两千行的消息，然后哨兵当天就被关掉了。
第一次会明说"首次运行：只建基准、不提醒"。

## 不刷屏，是这个技能能不能活下来的关键

哨兵是定时跑的，同一条记录每轮都命中是常态（库存一直低于阈值）。所以：

- 报过的记录**不再重复报**；
- 想周期性重复提醒就设 `remind_after_hours: 24`；
- 被去重压住了几条会**明说**（否则用户以为哨兵瞎了）；
- 阈值型的记录一旦不再命中就从状态里忘掉——下次再出问题还能报。

去重状态的落点运行时决定：优先 `$JDY_HOME`，再 `~/.jdy`，再宿主配置目录，
再会话工作目录；`--state` 可直接指定。**落在会话工作目录或临时目录时下一轮找不回来**
（等于每轮重报），这种情况屏幕上会有一句提示——想固定下来就设 `JDY_HOME`。
**写不进去时会退化成"每次都提醒"而不是"不提醒"**：重复是噪音，漏掉是事故。

`--dry-state` 只用于试规则，它不写状态，所以这一轮的命中下次还会再报。

## 定时跑

本技能不自带调度器——桌面 Agent 平台都有自己的定时任务，用平台的即可
（macOS 也可以用 `launchd`／`cron`）。建议：

- 间隔别小于 5 分钟。数据接口有频率上限，而哨兵的价值不在秒级。
- 定时跑的那条命令里**要带 `--send --yes`**，因为无人值守；但**第一次务必先手动
  预览一遍**，确认消息内容和条数正常，再放进定时任务。
- 先用 `--check` 验 webhook 通不通，它只发 GET，群里不留痕。

## 安全边界

- **只读**：本技能只查数据，不写回简道云任何东西。
- **推送是对外动作**：默认只预览，`--send` 才真发，非交互环境没有 `--yes`
  直接拒绝（退出码 4）。发进群收不回。
- webhook URL 里带密钥，打印一律掩码。
- 消息里只放你在 `message` 模板里点名的字段——想清楚哪些内容适合进群，
  群成员往往多于这条数据的相关人。
